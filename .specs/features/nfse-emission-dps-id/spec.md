# NFS-e Emission DPS_ID Specification

## Problem Statement

Currently, `nfse_emission` stores the XML payload and the numeric components (`dps_serial`, `dps_number`), but does not persist the full generated DPS identifier (`Id` attribute from `<infDPS>`). The national DPS ID is generated by `DpsXmlBuilder` with the standard `"DPS"` prefix (e.g., `DPS310620026637562000011300007000000000000042`). To allow direct database querying, auditing, and reconciliation without XML parsing, `nfse_emission` needs a `dps_id` column storing the generated DPS identifier without the `"DPS"` prefix.

## Goals

- [ ] Add `dps_id VARCHAR(50)` to `nfse_emission` via a new Flyway migration with an index for query performance.
- [ ] Map `dpsId` in `NfseEmissionEntity` matching the database schema.
- [ ] Strip the `"DPS"` prefix from the ID generated by `DpsXmlBuilder` and persist it into `nfse_emission.dps_id` during emission preparation.
- [ ] Maintain full idempotency, auditability, and rollback consistency.

## Out of Scope

| Feature | Reason |
| ------- | ------ |
| Backfilling historical emission rows with `dps_id` | Historical rows may lack sequence data; migration keeps `dps_id` nullable for pre-existing records. |
| Altering XML generation format or schema attributes | The XML `<infDPS Id="...">` attribute must still retain the `"DPS"` prefix required by the national XSD schema. |
| Changing public API response payload | The user requested persisting `dps_id` to the database; modifying external DTO contracts is out of scope unless explicitly requested. |

## Assumptions & Open Questions

Every ambiguity is resolved or recorded here.

| Assumption / decision | Chosen default | Rationale | Confirmed? |

| Column name and type | `dps_id VARCHAR(50)` | Standard 42-character national DPS ID (7 IBGE + 1 type + 14 doc + 5 serial + 15 number) fits comfortably in `VARCHAR(50)`. | yes |
| Column nullability | `NULL` (nullable) | Preserves compatibility with existing rows in `nfse_emission`. | yes |
| Column indexing | Index `idx_nfse_emission_dps_id` created on `(dps_id)` | Optimizes searching emissions by fiscal DPS ID. | yes |
| Prefix removal rule | Case-sensitive removal of `"DPS"` prefix if present (e.g. `rawId.startsWith("DPS") ? rawId.substring(3) : rawId`) | Matches the exact requirement to store the generated DPS ID without the "DPS" prefix. | yes |
| XML integrity | The `<infDPS Id="...">` attribute and XML signature retain `"DPS"` | Brazilian national NFS-e XSD requires `Id` to match pattern `DPS[0-9]{42}`. Only the database column stores the unprefixed value. | yes |
| Failure rollback | If emission preparation fails, `dps_id` persistence rolls back with the transaction | Part of the atomic emission preparation unit of work. | yes |

## User Stories

### P1: Persist DPS ID Schema Migration and Entity Mapping - MVP

**User Story**: As the backend database and persistence layer, I want `nfse_emission` to have a `dps_id` column mapped to `NfseEmissionEntity` so that the unprefixed DPS ID can be stored and queried.

**Why P1**: Foundation required before emission preparation can store the identifier.

**Acceptance Criteria**:

1. WHEN Flyway migration `V3__add_dps_id_to_nfse_emission.sql` runs THEN the system SHALL add `dps_id VARCHAR(50)` to `nfse_emission`.
2. WHEN migration `V3` runs THEN the system SHALL create index `idx_nfse_emission_dps_id` on `nfse_emission (dps_id)`.
3. WHEN JPA validates the schema against PostgreSQL THEN `NfseEmissionEntity` SHALL validate successfully with property `dpsId` mapped to `dps_id`.
4. WHEN an existing emission row without `dps_id` is loaded THEN `NfseEmissionEntity.getDpsId()` SHALL return `null` without error.

**Independent Test**: Execute Flyway migration against PostgreSQL container and verify column metadata, index presence, and JPA entity validation.

---

### P1: Populate and Persist DPS ID in Emission Preparation - MVP

**User Story**: As `NfseEmissionService`, I want to extract the generated DPS ID from `DpsXmlBuilder`, strip its `"DPS"` prefix, and store it on `NfseEmissionEntity` during preparation so that each new emission has its fiscal DPS ID persisted.

**Why P1**: Delivers the core requested capability for all new emissions.

**Acceptance Criteria**:

1. WHEN `DpsXmlBuilder` builds a DPS XML with `Id="DPS{42-digits}"` THEN the system SHALL provide or compute the DPS ID without the `"DPS"` prefix (`"{42-digits}"`).
2. WHEN a new emission request is prepared THEN `NfseEmissionService` SHALL set `dpsId` on `NfseEmissionEntity` before saving.
3. WHEN the prepared emission is persisted THEN `nfse_emission.dps_id` SHALL contain the 42-digit identifier without the `"DPS"` prefix.
4. WHEN an idempotent request hits an existing emission THEN the system SHALL return the existing emission without altering or regenerating `dps_id`.
5. WHEN emission preparation fails before commit THEN the transaction rollback SHALL ensure no emission row with `dps_id` is retained.

**Independent Test**: Call `NfseEmissionService.emit()` with a new request and verify that the persisted entity in PostgreSQL contains `dpsId` matching the generated XML ID without `"DPS"`.

---

## Edge Cases

- WHEN `DpsXml.id()` does not start with `"DPS"` (e.g. custom or mock value `12345`) THEN the system SHALL preserve the raw ID without error.
- WHEN `DpsXml.id()` is null or blank THEN `dpsId` SHALL remain null or empty without throwing a null pointer exception.
- WHEN the DPS number has leading zeros (padded to 15 digits) THEN all digits of the 42-character string SHALL be preserved in `dps_id`.
- WHEN an idempotent request is replayed THEN `dps_id` on the existing record SHALL remain untouched.
